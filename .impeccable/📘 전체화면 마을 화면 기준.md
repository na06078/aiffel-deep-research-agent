# 전체 화면 마을 스파이크 기준

## 승인과 범위

사용자 원문: “게임 화면같은 마을 같은 스크린이 화면 전체를 차지하는거고, 다른 부분들은 다 햄버거 메뉴나 팝업 같은걸로 확인”. 추가로 “스타듀 밸리, 동숲처럼 진짜 마을 느낌”과 입력 아래의 접이식 객체별 시간 트랙·기록 되감기를 승인했다. 대시보드뿐 아니라 여섯 집을 줄 세운 업무 배치도도 현재 목표가 아니다. 실제 모델/이미지 생성 없이 기존 CC0 에셋을 재사용한다. 연결 정본은 기술 명세20절·계약.ts·시간계약.ts·장면계약.ts다.

## Direction contract

### THESIS

마을은 대시보드 속 그림이 아니라 앱 화면 자체다. 세계가 모든 viewport를 채우고 업무 정보는 필요할 때만 그 위에 열린다. 기능 검사 수나 로그가 보이는 것을 이 화면 요구의 통과로 대신하지 않는다.

### OWN-WORLD

Kenney 16px 픽셀 에셋으로 구불구불한 길·광장·정원·숲/물가와 성격이 다른 장소를 연결한다. 동일한 집/PC6개나 장식 나무 띠를 늘어놓지 않는다. 건물·소품·밀도·동선의 차이로 생활 공간을 만들고 NPC의 실제 업무 장소를 유지한다. 외부 게임의 에셋을 복사하거나 마을 게임 전체를 추가하지 않는다. 흰 본문·상시 칼럼·진단 버튼 벽은 없다.

### STORY

입력으로 업무를 맡기고 NPC 활동을 관찰한다. 말풍선/종이/메뉴는 기존 상세·보고서·기록에 연결한다. 입력 아래 손잡이로 실제 객체별 시간 막대를 펼치고 완료된 실행의 시점을 이동해 마을과 기록을 함께 복기한다. 재생은 읽기 전용이며 실행/모델을 다시 시작하지 않는다. 측정 시간·대기·연출을 구별한다.

### FIRST VIEWPORT

(0,0)부터 브라우저 폭·높이 전체가 Pixi 마을이다. 작은 햄버거/모의 응답 표시/하단 입력과 그 아래 얇은 타임라인 손잡이만 상시 노출한다. 손잡이를 눌러 펼친 트랙 패널은 장면 위에 겹치며 입력은 그 위로 올라와 접근 가능하다. 상시 큰 표/로그/오른쪽 칼럼과 페이지 스크롤은 없다. 드로어/팝업/재생 전후에도 world bbox와 같은 canvas를 유지한다.

### FORM

사용자가 전체 화면 게임형 구조를 직접 지정하고 재제작을 승인했다. 배치 선택은 미결정이 아니며 카드형 대안·새 브랜드 추첨·이미지 comp를 추가하지 않는 code-led 수정이다. 기본 Experience, 업무 팝업만 Operate다.

### FINISH

unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

## 실제 판정

viewport 캡처를 열어 마을다운 장소·동선·밀도를 먼저 확인한다. world/canvas 경계·입력/손잡이/닫기/트랙/세부창 접근을 대조하고, 실제 완료 기록을 앞/중간/뒤로 반복 seek해 같은 시점의 위치/내용·호출수/DB/보고서 불변을 확인한다. 이전21/17/11이나 ship은 새 마을/재생 기능 수용이 아니다.
