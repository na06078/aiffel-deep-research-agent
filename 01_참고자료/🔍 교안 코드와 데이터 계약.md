- 확인 시각: 2026-11-05T16:56:08+09:00
- 성격: 승인된 기존 학습노트에서 추출한 교안 코드 보존본과 정적 연결 근거. 실행 파일이나 실행 결과가 아니다.
- 보존 기준: 코드 본문은 재작성하지 않고 원본 fenced block에서 추출한다. 개행은 LF로 정규화하고 끝 개행 하나를 붙인 후 SHA-256을 비교한다.
- 미검증: 현재 LMS 편집기 값과 전체 재대조, 원본 데이터 파일의 실제 규모·라이선스 파일, 설치·실행·API 호출·무료 적용은 확인하지 않았다.
- 주의: 교안의 설치·다운로드·키 입력·모델 호출·실행 셀은 아래에 자료로만 보존한다. 이번 단계에서 실행하지 않는다.
- 교안의 모델 값은 원형 보존한다. 이 프로젝트가 선택한 실행 모델은 `gpt-5.6-luna`이며 교안의 `gpt-4o-mini`를 실제 선택으로 오인하지 않는다.

## 3. 추가 연결 근거와 미확인 사항

### 3.1 데이터 제공처에서 확인한 것

공개 저장소 README는 `corpus.json`의 `docs`를 문서 제목→본문, `links`를 문서 제목→제목 목록으로 소개하고, ZIP 안에 `corpus.json`과 `결과자료.json`이 들어 있다고 설명한다. 이는 제공처 설명과 소비 코드가 요구하는 형식의 대조이며, 실제 JSON을 파싱한 결과가 아니다.[15]

읽기 전용 GitHub API 조회에서 `main`의 커밋은 `21f6625aeebc5629e34545c717969e80b62b47c1`, 그 커밋의 트리는 `cd66e643f7b8abbde2329efea0ba22dcf4441988`로 확인했다. 해당 트리를 직접 조회해 다음 파일 메타데이터를 확인했다. 커밋 SHA·트리 SHA·Git blob SHA를 다운로드 파일의 SHA-256과 혼동하지 않는다.[19][20]

| 경로 | Git blob SHA | API에 표시된 바이트 수 |
|---|---|---:|
| `README.md` | `7da1b9c1432c56e4286a694ddfb222f3ed575f02` | 5,366 |
| `data/deepresearch_d48_data.zip` | `c7bc03e7158a1e05c1018140ea80e0478ff56b12` | 404,037 |
| `data/결과자료.json` | `b064ad7246ffccc1d24fe279a63ba0eeb6c0d267` | 169,069 |

README 직접 GET은 HTTP 200이었고 응답 바이트의 Git blob SHA를 위 메타데이터와 대조해 일치했다. ZIP·JSON 본문은 아직 내려받지 않았으며 ZIP 멤버·전체 규모·링크 방향·파일 내부 라이선스·실제 다운로드 SHA-256은 미확인이다.

### 3.2 교안의 실제 입력·반환 계약

아래는 보존한 코드에 대한 정적 관찰이다. 실행 성공이나 실제 모델의 판단을 뜻하지 않는다.

| 단계 | 코드에서 읽는 값·반환하는 값 | LLM 여부 |
|---|---|---|
| 공통 상태 | `Research`: `question`, `plan`, `sections`, `visited`, `report`, `metrics`, `log`, `task`, `prior`. `sections`·`visited`·`log`는 `operator.add` 리듀서 | 상태 정의는 코드 |
| 기획 | `cards()`의 제목·앞 250자와 질문 → `제목`, `목차`, `배치`, `바퀴`; 목차 항목은 `절`, `지시`, `역할`, `시작문서`, `예산` | `ask()` 호출 |
| 배치 | `plan.배치`, 기존 절 원고 → `Send`별 `question`, `task`, `prior`; `task`에 `번호`, `피하기` 추가 | 코드 |
| 조사 | `탐색()`이 원문을 `read_one()`에 보내 요약 메모를 만들고 `다음문서()`로 후보 선택, `집필()`이 메모로 원고·자기신고 생성 | 문서 읽기·다음 선택·집필에서 호출 |
| 절 원고 | `번호`, `절`, `역할`, `본문`, `읽은문서`, `메모`, `인용`, `허위인용`, `충분`, `부족`; `visited`는 `[절 제목, 문서 제목]` 쌍 | 결과 집계는 코드 |
| 점검 | 최신 절을 제목으로 집계하고 `충분`을 확인해 부족한 절만 재위임. `최대바퀴`에 닿으면 부족 유무와 별도로 `라운드 소진` 종료 | 코드, 별도 LLM 없음 |
| 종합 | 절 번호순 정렬, 제목·각 본문 첫 90자로 머리말·맺음말 생성 후 절 본문은 그대로 이어 붙임 | 머리말·맺음말만 호출 |
| 평가 | 문장 분리와 `«문서명»` 정규식·읽은 문서·전역 `COST`로 지표 계산 | 코드, 별도 LLM 없음 |
| 단일 비교 | `단일에이전트()`는 문서를 순차 선택·읽기·전체 집필 후 평가 지표만 반환 | 같은 `ask()` 경로 사용 |

노드 7의 최종 정의는 본 문서 6절의 해당 셀을 기준으로 추적한다. 노트북 셀은 `globals()`로 노드를 바꾸고 여러 셀 끝에서 전체 그래프를 다시 실행하므로, 셀을 합쳐 실행하는 것으로 서비스 실행 모듈을 만들지 않는다. 보존본에는 원래 호출문도 그대로 있지만 이번 작업에서 실행하지 않았다.

### 3.3 구현 전에 구별해야 하는 코드 특성

| 관찰 근거 | 확인한 동작 | 기술 설계에서 다룰 것 |
|---|---|---|
| 노드 6 셀 5·노드 7 셀 5 `ask()` | `COST["calls"]` 증가는 재시도 루프 바깥에 있고 `llm.invoke()`는 루프 안에 있다. 입력 문자 계량은 system 메시지·실제 토큰과도 다르다 | 교안 비교용 논리 호출·문자 지표와 실제 전송 시도·토큰·예산 예약을 분리. 전역 가변 계량기를 실행 간 공유하지 않음 |
| 노드 7 셀 13 `evaluate()` | `인용` 목록을 만들 때 `if c in DOCS`로 미등록 인용명을 먼저 제외한다. 최종 지표의 `허위인용`은 그 목록과 전체 읽은 문서를 비교한다 | 미등록 인용·미열람 인용·다른 절의 문서 인용·내용 오귀속을 구별. 교안 지표 보존과 별도 무결성 검사의 관계는 기술 명세에 명시 |
| 노드 6 셀 7·노드 7 셀 7 `다음문서()` | 반환 전 확인은 `DOCS`에 있는지와 이미 읽었는지이며, 실제 제시한 `cand` 안에 있는지까지 검사하지는 않는다 | 후보·구역 제약 검증의 차이와 학습 기준/서비스 변형을 구별 |
| `jload()`·`집필()` | JSON 파싱 실패 시 기본값 반환이나 원문 일부 회수 경로가 있다. `충분` 값은 `bool()`로 변환한다 | 파싱·타입·관계 검증 실패를 정상 판단으로 꾸미지 않는 오류 계약. 교안 원문은 보존 |
| `절모음()`·`review()` | 최신 절을 제목 문자열로 집계한다 | 즉시 개입·제목 변경·동명 절·재위임의 식별자를 애플리케이션이 소유하는 설계 필요 |
| 노드 7 셀 16 `단일에이전트()` | 최종 보고서를 만든 후 지표만 반환한다 | 비교 실험에서 실제 보고서·입출력·조건도 보존하도록 서비스 결과 계약을 설계 |
| 노드 7 셀 19 | 제공된 `결과자료.json`을 읽어 과거 예시를 펼치는 별도 함수들 | 제공 예시와 이 앱의 실제 실행 기록을 섞지 않음. 정상 실행을 예시 재생으로 대체하지 않음 |

위 표는 아직 앱의 결함 재현·수정 결과가 아니다. 교안 학습의 구조와 서비스의 오류·비용·보존 요구를 함께 만족시키기 위한 설계 입력이다.

### 3.4 제공처 설명과 강의 기록의 불일치

- README는 `거문도 사건`에 들어오는 링크가 없어 링크 탐색으로 도달할 수 없다고 설명하지만, 노드 6의 저장 강의 기록은 다른 문서 8건에서 이 문서로 연결된다고 설명한다. 실제 `links` 데이터를 검사하기 전에는 어느 설명이 맞는지 확정하지 않는다.[15]
- README의 “어떤 모델의 창에도 한 번에 들어가지 않는다”는 일반화는 현재 선택 모델의 컨텍스트 판단 근거로 쓰지 않는다. 교안의 모델과 선택 모델은 다르며, 실제 입력 토큰 수·설정·선택 모델 문서를 따로 확인해야 한다.[2][15]
- README는 위키백과 본문에 CC BY-SA 4.0, 제공 실행 기록에는 교육 목적 사용·수정 허용을 설명한다. 이를 곧바로 향후 서비스의 모든 예시·보고서 재배포 권한이 확인된 것으로 확대하지 않는다. 실제 파일과 사용 방식에 따른 조건은 이후 확인한다.[15]
- README는 `collect.py`를 언급하지만 조회한 공개 트리의 파일 목록에는 해당 파일이 없었다. 수집기를 프로젝트에 존재하는 코드로 가정하지 않는다.[15][19]

지속 저장·즉시 개입·이벤트·보고서 변환의 공식 기술 근거와 제안 계약은 별도 기술 명세 초안에서 구별한다. 실제 모델 호출·SDK 파라미터 수락·외부 취소·원본 데이터 검증이 완료됐다고 판단하지 않는다.

````python
import json, operator
from pathlib import Path
from typing import Annotated, TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.types import Send

CORPUS = json.loads(Path("corpus.json").read_text(encoding="utf-8"))
DOCS, LINKS = CORPUS["docs"], CORPUS["links"]          # 문서 34건과 그 사이 링크

class Research(TypedDict):
    question: str                                # 설정 — 우리가 던지는 질문
    plan:     dict                               # ① 목차 · 역할 · 배정
    sections: Annotated[list, operator.add]      # ③ 서브에이전트가 올린 절 원고
    visited:  Annotated[list, operator.add]      # ③ (절, 문서) — 누가 무엇을 읽었나
    report:   str                                # ⑤ 완성된 보고서
    metrics:  dict                               # ⑥ 얼마나 잘했나
    log:      Annotated[list, operator.add]
    task:     dict                               # Send 로 서브에이전트 하나에게만 가는 지시
    prior:    dict                               # 재위임일 때 지난 바퀴의 원고

def plan(s: dict) -> dict:                       # ① 기획 — 섹션 4에서 채운다
    빈절 = {"절": "(빈 절)", "지시": s["question"], "역할": "큰그림 담당",
            "시작문서": "", "예산": 0}
    return {"plan": {"제목": s["question"], "목차": [빈절], "배치": [0], "바퀴": 1},
            "log": ["① 기획   목차 1절 (빈 노드)"]}

def dispatch(s: dict) -> dict:                   # ② 배치 — 섹션 5에서 채운다
    return {"log": [f"② 배치   서브에이전트 {len(s['plan']['배치'])}개 파견 (빈 노드)"]}

def researcher(s: dict) -> dict:                 # ③ 조사 — 섹션 6에서 채운다
    return {"sections": [{"번호": 0, "절": s["task"]["절"], "역할": s["task"]["역할"],
                          "본문": "", "읽은문서": [], "메모": [], "인용": [],
                          "허위인용": [], "충분": True, "부족": ""}],
            "visited": [],
            "log": [f"   ③ 리서처 에이전트 «{s['task']['절']}» 0건 읽고 0자 (빈 노드)"]}

def 절모음(s: dict) -> dict:                     # 재위임되면 같은 절이 두 번 올라온다 — 마지막 것만
    return {sec["절"]: sec for sec in s["sections"]}

def review(s: dict) -> dict:                     # ④ 점검 — 2일차 섹션 1에서 채운다
    return {"plan": {**s["plan"], "배치": []},
            "log": [f"④ 점검   {len(절모음(s))}절 중 빈 칸 0개 (빈 노드)"]}

def synthesize(s: dict) -> dict:                 # ⑤ 종합 — 2일차 섹션 2에서 채운다
    return {"report": "", "log": [f"⑤ 종합   {len(절모음(s))}절 → 보고서 0자 (빈 노드)"]}

def evaluate(s: dict) -> dict:                   # ⑥ 평가 — 2일차 섹션 3에서 채운다
    return {"metrics": {}, "log": ["⑥ 평가   지표 0개 (빈 노드)"]}

def fanout(s: dict):                             # ②가 여는 갈림길 — 섹션 5에서 채운다
    """절마다 Send 를 하나씩 띄운다. 빈 목록이면 곧장 점검으로 간다."""
    idxs = s["plan"].get("배치", [])
    if not idxs:
        return "review"
    return [Send("researcher", {"question": s["question"],
                                "task": s["plan"]["목차"][i], "prior": {}})
            for i in idxs]

def route(s: dict) -> str:                       # ④가 정한 갈림길 — 2일차 섹션 1에서 채운다
    return "more" if s["plan"].get("배치") else "done"

NODES = ("plan", "dispatch", "researcher", "review", "synthesize", "evaluate")

def build():
    g = StateGraph(Research)
    for name in NODES:
        g.add_node(name, globals()[name])                 # ← 이름으로 찾으니 갈아 끼울 수 있다
    g.add_edge(START, "plan")
    g.add_edge("plan", "dispatch")
    g.add_conditional_edges("dispatch", lambda s: globals()["fanout"](s),
                            ["researcher", "review"])     # ← ②⇉③ 팬아웃
    g.add_edge("researcher", "review")
    g.add_conditional_edges("review", lambda s: globals()["route"](s),
                            {"more": "dispatch", "done": "synthesize"})   # ← ②↔④ 재위임 루프
    g.add_edge("synthesize", "evaluate")
    g.add_edge("evaluate", END)
    return g

QUESTION = "1894년에 일어난 주요 사건들은 무엇이고 각각의 원인은 무엇인가?"
INIT = {"question": QUESTION, "plan": {}, "sections": [], "visited": [],
        "report": "", "metrics": {}, "log": [], "task": {}, "prior": {}}

COST = {"calls": 0, "sub_chars": 0, "coord_chars": 0}   # ⑥ 평가가 읽는 계량기

def run():
    COST.update(calls=0, sub_chars=0, coord_chars=0)   # 실행마다 0으로 — 안 그러면 호출 수가 누적된다
    return build().compile().invoke(INIT)

print(f"코퍼스 {len(DOCS)}건 · {sum(len(v) for v in DOCS.values()):,}자\n")
for line in run()["log"]:
    print(line)
````

````python
def 탐색(t: dict, prior: dict) -> tuple[list, list]:
    """예산만큼 읽고 (읽은 문서, 메모) 를 돌려준다. 코디네이터가 배정한 문서가 1순위."""
    read, notes = list(prior.get("읽은문서", [])), list(prior.get("메모", []))
    피하기 = t.get("피하기") or []
    다음 = t.get("시작문서") if t.get("시작문서") in DOCS else None
    for _ in range(t["예산"]):                      # 예산은 '이번 바퀴에 새로 읽을 수'
        if 다음 is None or 다음 in read:
            다음 = 다음문서(t, read, 피하기)        # 읽은 것이 다음 후보를 만든다
        if 다음 is None:
            break
        notes.append([다음, read_one(다음, t["지시"])])
        read.append(다음)
        다음 = None
    return read, notes


def 집필(t: dict, notes: list) -> dict:
    """모은 메모만 근거로 절 원고를 쓰고, 충분·부족을 스스로 신고한다."""
    자료 = "\n\n".join(f"[{d}]\n{n}" for d, n in notes) or "(읽은 자료 없음)"
    raw = ask(f"{역할문장(t)} 아래 자료만 근거로 보고서의 한 절을 써라. "
              "여섯 문장 이상 열두 문장 이하, 600자 이상. 문장마다 근거가 된 문서 제목을 «문서명» "
              "으로 붙여라. 자료에 없는 내용은 쓰지 마라. 지시를 자료로 다 채우지 못했으면 "
              "충분을 false 로 하고 무엇이 비었는지 적어라.\n"
              'JSON으로만: {"본문":"...","충분":true,"부족":""}',
              f"[맡은 절] {t['절']}\n[지시] {t['지시']}\n[모은 자료]\n{자료}")
    obj = jload(raw, {})
    text = str(obj.get("본문") or "")
    if len(text) < 100:                             # JSON 이 깨졌으면 원문에서 건진다
        text = re.sub(r'^\s*\{.*?"본문"\s*:\s*"?', "", raw, flags=re.S)[:2000].strip()
    return {"본문": text, "충분": bool(obj.get("충분")), "부족": str(obj.get("부족") or "")}


def researcher(s: dict) -> dict:
    """절 하나를 통째로 맡는다 — 탐색하고, 쓰고, 올린다."""
    t = s["task"]
    read, notes = 탐색(t, s.get("prior") or {})
    원고 = 집필(t, notes)
    인용 = re.findall(r"«([^»]+)»", 원고["본문"])
    sec = {"번호": t["번호"], "절": t["절"], "역할": t["역할"], "본문": 원고["본문"],
           "읽은문서": read, "메모": notes, "인용": 인용,
           "허위인용": [c for c in set(인용) if c not in read],
           "충분": 원고["충분"], "부족": 원고["부족"]}
    mark = "충분" if sec["충분"] else f"부족({sec['부족'][:18]})"
    return {"sections": [sec],
            "visited": [[t["절"], d] for d in read],
            "log": [f"   ③ {t['역할']} «{t['절'][:14]}» {len(read)}건 읽고 "
                    f"{len(원고['본문'])}자 · 인용 {len(인용)}곳 · {mark}"]}


def 절모음(s: dict) -> dict:
    """재위임되면 같은 절이 두 번 올라온다 — 마지막 것만 남긴다."""
    return {sec["절"]: sec for sec in s["sections"]}
````

````python
import json, operator
from pathlib import Path
from typing import Annotated, TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.types import Send

CORPUS = json.loads(Path("corpus.json").read_text(encoding="utf-8"))
DOCS, LINKS = CORPUS["docs"], CORPUS["links"]          # 문서 34건과 그 사이 링크

class Research(TypedDict):
    question: str                                # 설정 — 우리가 던지는 질문
    plan:     dict                               # ① 목차 · 역할 · 배정
    sections: Annotated[list, operator.add]      # ③ 서브에이전트가 올린 절 원고
    visited:  Annotated[list, operator.add]      # ③ (절, 문서) — 누가 무엇을 읽었나
    report:   str                                # ⑤ 완성된 보고서
    metrics:  dict                               # ⑥ 얼마나 잘했나
    log:      Annotated[list, operator.add]
    task:     dict                               # Send 로 서브에이전트 하나에게만 가는 지시
    prior:    dict                               # 재위임일 때 지난 라운드의 원고

def plan(s: dict) -> dict:                       # ① 기획 — 1일차 섹션 4에서 채운다
    빈절 = {"절": "(빈 절)", "지시": s["question"], "역할": "큰그림 담당",
            "시작문서": "", "예산": 0}
    return {"plan": {"제목": s["question"], "목차": [빈절], "배치": [0], "바퀴": 1},
            "log": ["① 기획   목차 1절 (빈 노드)"]}

def dispatch(s: dict) -> dict:                   # ② 배치 — 1일차 섹션 5에서 채운다
    return {"log": [f"② 배치   서브에이전트 {len(s['plan']['배치'])}개 파견 (빈 노드)"]}

def researcher(s: dict) -> dict:                 # ③ 조사 — 1일차 섹션 6에서 채운다
    return {"sections": [{"번호": 0, "절": s["task"]["절"], "역할": s["task"]["역할"],
                          "본문": "", "읽은문서": [], "메모": [], "인용": [],
                          "허위인용": [], "충분": True, "부족": ""}],
            "visited": [],
            "log": [f"   ③ 리서처 에이전트 «{s['task']['절']}» 0건 읽고 0자 (빈 노드)"]}

def 절모음(s: dict) -> dict:                     # 재위임되면 같은 절이 두 번 올라온다 — 마지막 것만
    return {sec["절"]: sec for sec in s["sections"]}

def review(s: dict) -> dict:                     # ④ 점검 — 섹션 1에서 채운다
    return {"plan": {**s["plan"], "배치": []},
            "log": [f"④ 점검   {len(절모음(s))}절 중 빈 칸 0개 (빈 노드)"]}

def synthesize(s: dict) -> dict:                 # ⑤ 종합 — 섹션 2에서 채운다
    return {"report": "", "log": [f"⑤ 종합   {len(절모음(s))}절 → 보고서 0자 (빈 노드)"]}

def evaluate(s: dict) -> dict:                   # ⑥ 평가 — 섹션 3에서 채운다
    return {"metrics": {}, "log": ["⑥ 평가   지표 0개 (빈 노드)"]}

def fanout(s: dict):                             # ②가 여는 갈림길 — 1일차 섹션 5에서 채운다
    """절마다 Send 를 하나씩 띄운다. 빈 목록이면 곧장 점검으로 간다."""
    idxs = s["plan"].get("배치", [])
    if not idxs:
        return "review"
    return [Send("researcher", {"question": s["question"],
                                "task": s["plan"]["목차"][i], "prior": {}})
            for i in idxs]

def route(s: dict) -> str:                       # ④가 정한 갈림길 — 섹션 1에서 채운다
    return "more" if s["plan"].get("배치") else "done"

NODES = ("plan", "dispatch", "researcher", "review", "synthesize", "evaluate")

def build():
    g = StateGraph(Research)
    for name in NODES:
        g.add_node(name, globals()[name])                 # ← 이름으로 찾으니 갈아 끼울 수 있다
    g.add_edge(START, "plan")
    g.add_edge("plan", "dispatch")
    g.add_conditional_edges("dispatch", lambda s: globals()["fanout"](s),
                            ["researcher", "review"])     # ← ②⇉③ 팬아웃
    g.add_edge("researcher", "review")
    g.add_conditional_edges("review", lambda s: globals()["route"](s),
                            {"more": "dispatch", "done": "synthesize"})   # ← ②↔④ 재위임 루프
    g.add_edge("synthesize", "evaluate")
    g.add_edge("evaluate", END)
    return g

QUESTION = "1894년에 일어난 주요 사건들은 무엇이고 각각의 원인은 무엇인가?"
INIT = {"question": QUESTION, "plan": {}, "sections": [], "visited": [],
        "report": "", "metrics": {}, "log": [], "task": {}, "prior": {}}

COST = {"calls": 0, "sub_chars": 0, "coord_chars": 0}   # ⑥ 평가가 읽는 계량기

def run():
    COST.update(calls=0, sub_chars=0, coord_chars=0)   # 실행마다 0으로 — 안 그러면 호출 수가 누적된다
    return build().compile().invoke(INIT)

print(f"코퍼스 {len(DOCS)}건 · {sum(len(v) for v in DOCS.values()):,}자\n")
for line in run()["log"]:
    print(line)
````

````python
def 탐색(t: dict, prior: dict) -> tuple[list, list]:
    """예산만큼 읽고 (읽은 문서, 메모) 를 돌려준다. 코디네이터가 배정한 문서가 1순위."""

    피하기 = t.get("피하기") or []
    다음 = t.get("시작문서") if t.get("시작문서") in DOCS else None
    for _ in range(t["예산"]):                      # 예산은 '이번 라운드에 새로 읽을 수'
        if 다음 is None or 다음 in read:

        if 다음 is None:
            break
        notes.append([다음, read_one(다음, t["지시"])])
        read.append(다음)
        다음 = None
    return read, notes
````
